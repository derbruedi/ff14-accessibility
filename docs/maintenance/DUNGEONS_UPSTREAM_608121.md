# Подземелья и сравнение с автором — 6.08.121

Проверено 17 октября 2026. Запрос: персонаж не начинает движение в крепости,
название которой пользователь помнит как «форт/крепость земель».
Рабочее соответствие — Dzemael Darkhold, крепость Дземаэль. Пользователь
подтвердил отсутствие движения, но не подтвердил английское название.
В доступном dalamud.log от 16 октября есть Састаша; попытки в Дземаэль нет.

## Найденное различие vnavmesh

Установлена vnavmesh 1.2.3.14, исходный коммит
`972d77218477548a175d97703ccab24d01302015`, DLL SHA-256
`889EBFF40D92DB2DF4B4C190F1D81B3971E538908E459F6297F53FEA017E3723`.
Официальный каталог puni.sh на момент проверки предлагает эту же версию/API15.

В этой сборке `Z0171DzemaelDarkhold` зарегистрирована только для территории 171.
Авторский коммит vnavmesh
[`6fc80725`](https://github.com/awgil/ffxiv_navmesh/commit/6fc80725eb8290472eee433fc4be7ee06ec79357)
добавил территорию 1330 к тому же классу. Это обновлённая крепость;
игровые таблицы подтверждают одинаковый фон `ffxiv/roc_r1/rad/r1r1/level/r1r1`.
Класс исправляет построение сетки возле дверей. Сравнение исходников:
[установленная версия](https://github.com/awgil/ffxiv_navmesh/blob/972d77218477548a175d97703ccab24d01302015/vnavmesh/Customizations/Z0171DzemaelDarkhold.cs),
[исправление автора](https://github.com/awgil/ffxiv_navmesh/blob/6fc80725eb8290472eee433fc4be7ee06ec79357/vnavmesh/Customizations/Z0171DzemaelDarkhold.cs).

DungeonMeshCompatibility переносит именно эту регистрацию в память работающей
зависимости: 1330 использует существующий экземпляр исправления 171. Изменение
выполняется при явной команде навигации в 1330, только когда построитель свободен.
Перед записью проверяются версия, SHA-256 DLL, структура реестра и настоящий тип
исправления. Неизвестная сборка не изменяется; существующая поддержка 1330
не заменяется. Файлы vnavmesh, настройки, остальные территории и координаты
не изменяются. После регистрации запрашивается штатное перестроение сетки;
игрок получает русское сообщение и повторно включает движение после ожидания.
Автоматического возобновления движения нет. Регистрация живёт до перезапуска
зависимости; при следующем запуске проверяется снова.

В отдельном процессе проверена настоящая установленная DLL: результат `Applied`,
повтор — `AlreadySupported`. Это проверка регистрации, а не прохождения дверей.
Сохранённой сетки `r1r1` на компьютере нет. Поэтому связность пути в крепости
вне игры не проверена; утверждать, что найдено объяснение всех остановок, нельзя.

## Маршруты и объекты

- Для записанных точек подземелья сохранена измеренная высота. Вместо поиска
  поверхности в столбе высотой 200 метров допускается только близкая точка
  в пределах 3 метров; при её отсутствии исходная точка передаётся движению автора.
  Неполный ответ сетки по-прежнему не запрещает запуск движения.
- Из аргументов Interactable сохраняется числовой номер объекта. Поиск двери
  или NPC использует этот номер, положение и высоту; локализованное имя не
  участвует в выборе. При отсутствии номера неоднозначные механизмы не угадываются.
- Загруженный экземпляр получает собственные координаты и номер с первого
  запроса движения. Сохранены прежние проверки исчезновения и подмены объекта.
- Точки с NaN/Infinity исключены. Старые JSON и конструктор DungeonStep совместимы.
- `/acc navstatus` читает готовность сетки и число точек текущей зоны,
  перечитывает добавленные файлы и пишет точные сведения `[DungeonNav]` в журнал.
- `/acc navrebuild` останавливает наше движение и вызывает штатное перестроение
  vnavmesh, не удаляя старые файлы. При уже идущем построении сообщает процент.

Настоящие файлы DungeonPaths проверены инструментом `tools/dungeon-route-check`:
235 территорий, 232 с точками; 1127–1129 — учебные сценарии с управляющими
действиями без позиционного маршрута. У старой Дземаэль 36 точек, у обновлённой
11, в каждой по два механизма с номером. Сторонние данные маршрутов не включены
в исходники или ZIP мода.

## Сравнение FF14Accessibility с автором

`upstream/main` и последний опубликованный релиз автора остаются на
`e006e9d`, v6.08.35; их история уже входит в наш форк. Дополнительно проверена
неопубликованная ветка `release/6.08.118-merge`,
`55b17bc33e53b7916e38b02e1d5138118fdf4b15`. Она содержит импорт нашего более
раннего кода вместе с новыми авторскими возможностями. Целиком заменять ею
наш код означало бы потерять более поздние исправления.

Перенесены с сохранением русских сообщений:

| Возможность | Результат |
| --- | --- |
| Инвентарь по Ctrl+F3 | Категории, предметы, описание и штатное меню точной ячейки; при необходимости сначала открывается сумка |
| Оружейный сундук | Группы по доступным классам, вход Num0, возврат плюсом; внутри остаются полные параметры, HQ, материя и точная физическая ячейка |
| Экипировка персонажа | Название слота, пустой слот, прочность и связь с духом именно выбранного экземпляра; русские подписи |
| Охотничий журнал | Закреплённый список мест появления по BNpcName и территории; при отсутствии данных сохраняется поиск по области, живой противник имеет приоритет |
| Сезонные события | Действующая фаза фестиваля и места FATE из сценария задания вместо постоянного списка устаревших событий |
| Столпервиль/Blunderville | Направление, звук и Num5 для пяти трасс; игрок двигается и прыгает сам, обход препятствий не обещается |
| Обмен между игроками | Партнёр, предметы, HQ, гил и изменения подтверждения читаются без автоматического принятия сделки |
| Подтверждение с удержанием | Клавиша остаётся у штатного таймера игры; раннее отпускание сообщается; Enter и Num0 не подтверждают следующее окно тем же удержанием |
| Союзники и противники | Дополнительно учитывается нативный признак дружественного NPC по цвету имени; неизвестные состояния не скрывают возможного противника |

Не перенесены устаревшие варианты поиска ближайшего эфирита, потеря BaseId,
старые стрелки обучения, чтение текста соседних кнопок, старый счёт рангов
магазина, прежний доступ к русским таблицам и удаление нашей маршрутизации заданий.
Файлы V19 и русские справочники сохранены. Сравнение не объявляется полным Git merge:
из экспериментальной ветки перенесены проверенные изменения по смыслу.

## Обязательная проверка в игре

1. В обновлённой Дземаэль выбрать близкий объект/противника и включить движение.
   Первый запрос на старой vnavmesh должен сообщить о перестроении, следующий
   после готовности — начать путь. Проверить двери, механизм, босса, оба режима
   навигации, остановку, повтор и новую загрузку плагина.
2. В Састаше и другом подземелье проверить те же команды, обычные цели,
   неподвижный и переместившийся объект; исключить переход на соседний этаж.
3. При остановке выполнить `/acc navstatus`, затем при необходимости
   `/acc navrebuild`, дождаться готовности и повторить движение. Сохранить свежий
   dalamud.log с `[DungeonNav]`, `[Nav]` и сообщениями vnavmesh.
4. С NVDA/Tolk проверить Ctrl+F3, классы сундука, меню предмета при удержании Num0,
   пустые слоты, одинаковые вещи с разной прочностью, торговца и обмен игроками.
5. Проверить охотничий журнал с данными и без них, действующее событие, Столпервиль,
   обычное подтверждение и удержание с ранним отпусканием. Повторить на английском
   и немецком без русских подстановок.
