# Проверка названий меню Num+

Проверка читает таблицы установленной игры без её запуска. Нужны .NET SDK 10
и текущие библиотеки Dalamud, как для основной сборки.

```powershell
dotnet run --project tools/main-menu-check/MainMenuCheck.csproj -c Release -- 'ПУТЬ_К_GAME\sqpack' 'artifacts/logs/main-menu.json'
```

`ButtonClick.Param` семи кнопок `_MainCommand` обозначает строку
`MainCommandCategory`, а не `MainCommand`. Журнал игрока от 29 сентября 2026
показывает: параметр 2 открывает задания, 4 — путешествия, 7 — систему.
Старая версия называла их «Персонаж», «Журнал» и «Журнал собирательства».

Инструмент вызывает тот же `MainCommandMenu.ReadCategoryName`, что и чтение
кнопок в плагине. Проверяет все семь разделов, русский режим поверх четырёх
языков клиента, сохранение исходных названий в остальных режимах и отсутствие
выдуманного имени для пустой или отсутствующей строки. Отдельно проверяет
связь настоящих журналов собирательства и ремесла с разделом `Logs` (3),
а журнала заданий — с `Duty` (2).

Порядок разделов и положение Gathering Log также описаны в
[официальном руководстве FFXIV](https://na.finalfantasyxiv.com/game_manual/view/).

Эта проверка не нажимает клавиши и не подтверждает открытие окна в живой игре.
После установки проверить Num+ → Журналы → Журнал собирательства → Num0,
затем остальные шесть разделов и возврат назад. Для закрытых игровых функций
действуют обычные условия открытия персонажем.
